# AI 可复用经验原稿契约

`.cap/experience.md` 是本 Task 的**唯一经验原稿**。它供人逐字审计，也供确定性脚本生成 `record_experience` 载荷。`task-context.md` 记录代码事实和调用链；`experience.md` 只记录下一次 Agent 能直接用于召回、判断、定位和验收的耐久知识。

## 判断标准

一条经验必须让未参与本 Task 的 Agent 回答六个问题：

1. 什么需求、症状或检索词应召回它？
2. 当时为什么失败，而不是只知道改了什么？
3. 遇到同类情况必须遵守什么条件化决策？
4. 从哪些业务入口、文件或符号切入，哪些不变量不能破坏？
5. 用什么动作和可观察结果证明正确，失败长什么样？
6. 哪些协议、依赖或代码变化会让经验失效，届时去哪里复核？

只列接口、类名、字段映射或完整调用链只能算上下文，不能算经验。只写“参考类似实现”“按现有方式处理”“完成需求”同样不合格。

## 原稿模板

```md
---
schema: cap-experience/v1
title: <描述问题模式和决策，不写“完成某需求”>
task-id: <团队模式 Task；纯本地可空>
source-commit: <本经验验证对应的完整 Commit SHA>
---

## 复用触发与检索线索 / Reuse triggers and retrieval cues
- 触发：当<未来需求/场景/症状>时。
- 关键词：<业务词、协议词、错误特征、核心符号>。
- 症状：<可观察异常；无独立症状时可省略>。

## 问题与根因 / Problem and cause
- 问题：<原方案造成的具体后果>。
- 根因：<机制层原因，不是“代码有 bug”>。
- 失败做法：<尝试过但不应重复的路径，以及为何失败>。

## 决策与行动 / Decision and actions
- 决策：当<条件>时，必须/禁止/应先<规则>，因为<机制>。
- 行动 1：<下一次 Agent 可执行的第一步>。
- 行动 2：<必要的后续动作>。

## 实现锚点与不变量 / Implementation anchors and invariants
- 入口：<业务入口、配置入口或核心模块>。
- 改动点：<repo 相对文件路径和可选符号；不要贴代码正文>。
- 不变量：<状态、幂等、资金、兼容或安全约束>。

## 验证配方 / Verification recipe
- 验证动作：<测试层级、场景或稳定命令>。
- 通过信号：<可观察、可判定的正确结果>。
- 失败信号：<出现即说明规则未落实的结果>。

## 适用前提 / Preconditions
- <依赖、版本、架构或配置前提>。

## 禁用场景 / Do not use when
- <反例、禁区或不能照搬的相似场景>。

## 失效信号 / Invalidation signals
- 失效信号：<哪些协议、依赖、状态枚举或实现变化会推翻本经验>。
- 复核位置：<变化后应重新检查的文档、文件或配置>。

## 证据与结果 / Evidence and outcome
- 证据：commit:<与 source-commit 相同的完整 SHA>
- 证据：.cap/verify/<同 Commit 验证报告>.md
- 结果：<最终通过数量、状态收敛或风险消除等事实>。
```

## 信息取舍

- 保留能改变下一次 Agent 决策或动作的信息；删除一次性的过程播报。
- 实现锚点只列最小入口、关键改动点和不变量，不复制整张调用链。
- 验证配方记录可复现动作和观测信号，不用“已验证”“测试通过”代替证据。
- 经验允许包含 repo 相对路径和符号名；禁止代码正文、本机绝对路径、内网地址、账号和密钥。
- 同一 Task 有多条互不相关的教训时，应分别形成独立 Task/经验，不把不同主题堆进一篇原稿。

## 生成与质量门

实现和验证完成后，Agent 基于 `spec / task-context / diff / verify / review` 主动编写原稿，但这些输入都不是经验真值；原稿写成后由 `scripts/cap-experience-payload.mjs` 做确定性解析和质量检查。

生成器拒绝：缺任一核心段、只有调用链、宽泛空话、决策没有“条件 → 必须/禁止/先后动作”、没有实现锚点或不变量、没有可观察验证结果、缺失效信号、Commit 不一致、证据失败、软链逃逸、绝对路径或敏感信息。失败时修原稿或证据，不回退为从其他 `.cap` 文件猜测经验。
