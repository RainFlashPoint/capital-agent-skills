# Capital Agent 故障恢复手册

恢复时先保住本地事实，再恢复远程记录。不要删除 `.cap`、Git Commit 或 Outbox 来“清理”状态，也不要用聊天里的“已完成”覆盖机器状态。

## 通用恢复顺序

```text
1. 锁定当前 Git 根目录、分支、HEAD 和工作树
2. 读取 .cap/STATE.md、task-context.md、verify/、review/
3. 运行 cap-status.mjs，确认 Task、Session、Outbox 和下一动作
4. 先处理身份不一致，再处理平台连接，再处理测试/评审阻塞
5. 恢复后按依赖顺序重放 Outbox；每条事件成功才 ack，失败保留
6. 重新运行验证并刷新 .cap 证据，最后再提交或发布
```

## 常见故障

| 现象 | 判断 | 恢复动作 | 禁止做法 |
|---|---|---|---|
| MCP 未加载 | `restart_required` | 重启客户端；或明确选择本次本地继续 | 静默声称平台已连接 |
| 直接探测失败 | `direct_probe_unavailable` | 继续调用 MCP；MCP 也失败时转离线执行 | 把 DNS/探测失败直接当平台断网 |
| 平台暂时不可用 | MCP 调用失败 | 本地继续，写入当前 Task 的 Outbox；恢复后按 `replay-plan` 重放 | 上传代码正文、删除待同步事件 |
| Task/Session 串台 | `session_root_mismatch` 或 boundary blocked | 回到锁定仓库；跨项目先写交接摘要并显式切换，重建 Task/Session | 直接读取或覆盖另一个仓库的 `.cap` |
| 等待远程 Commit | `pushRequired=true` | 先确认精确 Commit 和目标远程，再推送；推送后补报 Delivery | 先创建 Test Action 再推送 |
| Test Provider 不可用 | Action 为 `ready` 且原因是环境阻塞 | 保留 Action，补齐/切换 Provider；必要时由 Server/Linux Runner 执行 | 把本地 PASS 写成 Server PASS |
| Action 失败 | Test/Review 为 `failed` 或 `needs_changes` | 按 finding 修复，生成新 Commit，再创建新候选 Action | 在同一个 Review Run 中改代码并自签通过 |
| Outbox 待同步 | `pending > 0` | 只重放属于当前 Task 的事件；历史事件先取得授权 | 把历史 Task 事件混入当前任务 |
| Delivery 身份不匹配 | branch、Task、Commit 或路径校验失败 | 修正请求中的身份；重新生成幂等键并重试 | 强行改 Task 分支或复用旧幂等键 |
| 本地状态显示已通过但页面未通过 | `localExecution` 与 `serverDelivery` 不同 | 以 Server canonical projection 为准，等待/补交对应 Action | 从本地 STATE 推断 Server Gate |
| 经验沉淀被拒绝 | 外部知识库策略拒绝 | 保留本地意图、改动路径和验证证据；下次在授权环境重试 | 通过变通方式上传私有代码或路径 |

## Outbox 恢复

Outbox 只保存事件元数据：Task/Session ID、分支、Commit、改动路径、验证摘要和幂等键。恢复前执行：

```bash
node scripts/cap-status.mjs <repo> --json --mcp-runtime loaded
node scripts/cap-outbox.mjs replay-plan <repo>
```

依赖顺序是：创建/绑定 Task → 创建 Session → 普通 Delivery → 候选 Delivery → Test/Review Action。事件成功后才 `ack`；失败执行 `fail` 并保留原始错误。历史 Task、旧 Session 或无归属事件必须单独标记，不能因为当前任务恢复就自动发送。

## 状态文件修复

如果 `.cap/STATE.md` 与 Git 不一致，先复制一份到 `.cap/local-state/stale/`，再用当前 `HEAD`、分支和工作树重建状态。验证报告必须写明 Action ID、源 Commit、Provider 终态和 Server Gate；`ENV_BLOCKED` 只能写阻塞，不能写 PASS。完成后检查：

```bash
git diff --check
git status --short
node scripts/cap-status.mjs <repo> --json --mcp-runtime loaded
```

## 事故记录

每次恢复至少记录时间、Task、Session、仓库、分支、Commit、故障码、采取的动作和最终证据路径。Platform 删除/审计、Bridge Token、Action 权限和 Provider Lease 属于独立安全专项，本手册不替代那些专项的审计要求。
